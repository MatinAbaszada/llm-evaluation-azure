Hello professors, thank you for being here. My thesis is "Empirical Evaluation and Cost Optimization of Large Language Models in Cloud Environments," supervised by Professor Ivan Ovsyannikov. In this thesis, I evaluate six cloud-hosted LLMs under a single unified framework and compare three optimization strategies.

Let me begin with my motivation. As you know, LLMs are becoming more and more popular, and enterprises increasingly want to integrate them into their systems. However, the reality is that hosting LLMs  locally requires expensive infrastructure, such as GPU clusters and cooling, which most companies cannot afford. Cloud environments already exist that provide all the resources needed to deploy an LLM and handle the operational and security overhead, so consumers simply pay per usage. One of the industry leaders in this space is Microsoft Azure. Azure is essentially a cloud environment where you can deploy any LLM and pay only for what you use. But which model you deploy really matters, because in the cloud the strongest model is not necessarily the best one. For example, a model that improves accuracy by only a few percentage points can easily cost 20 times more per request. This is what motivated me to compare LLMs using a single metric that combines accuracy, cost, and latency.

There is already a lot of literature on LLMs, but several gaps remain. First, most existing work compares models based on accuracy or cost in isolation. Second, optimization strategies are usually evaluated against their own internal goals, not under one unified framework. And third, very few studies test these strategies in a real cloud environment. My thesis answers three main research questions. First, how do LLMs differ in the cloud, and which one should we choose when accuracy, latency, and cost are all taken into account together? Second, do reasoning-enabled models actually justify their higher cost and longer inference times, and in which cases are they the best choice? And third, can we improve cost-efficiency through an optimization strategy?

To answer these questions, I deployed six LLMs on Microsoft Azure — you can see the list here. Except for the mini models and gpt-4.1, all of them are reasoning models, so the set is balanced: three reasoning and three non-reasoning models. To test the models, I used five benchmark datasets, each covering a different aspect such as coding, general knowledge, mathematics, and so on. I then repeated the same tests with three different optimization strategies, which I will explain in detail in the upcoming slides. Finally, all results were evaluated under the same economic reward function.

Let me walk you through this reward function step by step. The reward measures how well a model performed on a single request, and it combines three things: the cost of that request (in dollars), the latency of that request (in seconds), and a single boolean error variable that is 0 when the model's answer is correct and 1 when it is wrong. The two Greek letters, lambda-latency and lambda-error, are penalty weights. They are not fixed — they are parameters that we, as the users, set according to our priorities. For example, if low latency is critical for our application, we increase lambda-latency; if accuracy is critical, we increase lambda-error. We then compute the reward for each model under those weights and pick the best one. The reason the reward is negative is that we treat it as a penalty rather than a utility: a perfect model would have zero cost, zero latency, and zero errors, which gives a reward of exactly zero — the theoretical maximum. Every real model can only move away from that ideal, so its reward is always negative, and the closer to zero, the better.
